# Облако для GitHub Pages

Сайт остаётся статическим на GitHub Pages. Supabase Auth обслуживает email/пароль, Postgres — личные каталоги. Бесплатный тариф выбирается в панели Supabase; сайт не включает платные услуги автоматически.

1. Создайте проект Supabase на Free.
2. Выполните [setup.sql](setup.sql) в SQL Editor. Скрипт создаёт таблицу, три политики RLS и функцию записи с проверкой версии. Повторное выполнение не стирает данные.
3. Authentication → URL Configuration: Site URL и Redirect URLs должны содержать полный адрес вашего Pages с завершающим `/`. Для основного сайта это `https://rumm1.github.io/aitu-course-tracker/`.
4. Authentication → Sign In / Providers → Email: включите Email и отключите **Confirm email**, затем сохраните. Для текущего режима сайта регистрация должна сразу возвращать сессию без письма. Владение введённым email при этом не проверяется. Сайт проверяет эту настройку до регистрации и сообщает, если она ещё не применена на сервере.
5. SMTP для регистрации в этом режиме не нужен. Восстановление пароля письмом выключено в интерфейсе (`passwordRecoveryEnabled:false`), поскольку почта не подключена. Если впоследствии настроите SMTP, можно включить эту функцию в `src/cloud-config.js`. Для возврата подтверждения email нужно согласованно включить Confirm email в панели и `emailConfirmationRequired:true` в конфигурации сайта.
6. В `src/cloud-config.js` укажите Project URL и **Publishable key** (`sb_publishable_…`). Secret / service_role / пароль базы нельзя добавлять в исходники или браузер. Публикуйте после проверки RLS.
7. Откройте `/#account` и зарегистрируйтесь: личный аккаунт откроется сразу. Перенесите свою прежнюю локальную копию кнопкой в аккаунте. На телефоне войдите с тем же email и паролем. Ранее созданным неподтверждённым аккаунтам может потребоваться отдельная активация владельцем проекта; повторная регистрация не должна использоваться для обхода владения существующим аккаунтом.

Таблица `course_tracker_data` имеет ключ `(user_id, space)`. Политики разрешают доступ только при `auth.uid() = user_id`. `space` — имя репозитория, поэтому один аккаунт может иметь независимые копии на разных сайтах. Для полностью самостоятельной инфраструктуры владелец копии меняет конфигурацию на свой проект Supabase.

`save_course_tracker` работает с правами вызывающего пользователя (`security invoker`) и проверяет ожидаемую ревизию. Конфликт версии вызывает повторное чтение и объединение изменений. Облачная запись ограничена 5 МБ. Локальные PDF и ссылки на IndexedDB-документы из отправки исключены.

Проверено автоматически: объединение изменений двух устройств, конфликт ревизий, сохранение без сети, восстановление соединения, отсутствие файлов в запросах, вход/выход и изоляция двух пользователей в браузерных тестах с тестовым API. Публичный API рабочего проекта отдельно проверяется на запрет чтения/записи без входа. Настоящая доставка email зависит от настроек вашего SMTP.

Документация: [email/password](https://supabase.com/docs/guides/auth/passwords), [SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Free и ограничения](https://supabase.com/pricing).
