# Курс за курсом

Персональное пространство для обучения: курсы, понятный план, прогресс и сертификаты в одном месте. Каталог доступен сразу: **109 уникальных позиций** — 93 курса, 2 проекта, 12 специализаций и 2 профессиональные программы. Исходный план включает 28 позиций при выборе обеих версий архитектуры.

Опубликованный сайт: **[Курс за курсом](https://rumm1.github.io/aitu-course-tracker/)**.

## Что умеет сайт

- Обзор с дедлайном, прогрессом и очередью курсов; поиск, фильтры, собственный план и закреплённые приоритеты.
- Предметы CAP, SEC, QA, ARCH и TE; версии UML / Go; связи с неделями и подтемами с указанием источника SE, XLS или LIST.
- Ручные статусы, импорт PDF, CSV и JSON, личные ссылки сертификатов и открытие локального PDF.
- Локальная папка сертификатов в поддерживаемом настольном браузере, резервная копия JSON и проверка неоднозначных документов.
- Светлая и тёмная темы, оформление по настройке системы, карточки и компактный список курсов.
- Массовая вставка списков Coursera, фактический прогресс активных курсов и необязательный локальный перенос через расширение Chrome.

Кнопка темы в шапке переключает светлое и тёмное оформление. В настройках можно выбрать оформление по теме системы. Переключатель над каталогом меняет карточки на список: поиск, фильтры и действия курсов работают в обоих видах. Выбранные тема и вид каталога сохраняются в текущем браузере. Анимации учитывают системную настройку уменьшения движения.

Дедлайн — **10 ноября 2026 включительно**, Казахстан (UTC+5). Отсчёт заканчивается `2026-11-11T00:00:00+05:00`. После дедлайна сайт продолжает работать. Прохождение курса, покрытие темы и решение учебного заведения о перезачёте учитываются отдельно; ориентиры 90+ и 95 не являются полученными оценками.

## Публикация в GitHub Pages

1. Загрузите проект в GitHub-репозиторий с основной веткой `main`. Папки `node_modules` и `dist`, личные отчёты и сертификаты загружать не нужно.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. В **Actions** запустите **Publish GitHub Pages → Run workflow** или отправьте коммит в `main`.
4. Дождитесь успешных заданий `build` и `deploy`. Фактическая ссылка появится у deployment / окружения `github-pages`.

Формат адреса для обычного project site: `https://USERNAME.github.io/REPOSITORY/`. Это шаблон, а не подтверждение публикации. Workflow автоматически задаёт префикс `/<имя-репозитория>/`, в том числе для PDF worker. Навигация использует hash, поэтому обновление адреса вида `/#certificates` не требует настройки сервера.

После публикации пользователю достаточно открыть ссылку. Аккаунт в приложении и локальный запуск не требуются.

## Локальная разработка

Нужен Node.js 24 и npm. В PowerShell при ограничении выполнения `npm.ps1` используйте `npm.cmd`.

```sh
npm ci
npm test
npm run build
npm run dev
```

Откройте адрес, напечатанный Vite. Не открывайте `index.html` через `file://`: приложению нужны HTTP(S), JavaScript и IndexedDB. Результат сборки находится в `dist/`.

Для проверки сборки с префиксом в PowerShell:

```powershell
$env:BASE_PATH = '/REPOSITORY/'
npm.cmd run build
Remove-Item Env:BASE_PATH
```

## Импорт результатов

### Проверить мой прогресс без API

На обзоре нажмите **«Проверить мой прогресс»** или **«Учесть уже пройденные»**. Если активного расширения с результатами нет, сразу откроется массовая вставка — подключать почту, скачивать сертификаты или настраивать API не требуется.

1. Откройте [«Моё обучение» Coursera](https://www.coursera.org/my-learning).
2. Выберите «Завершённые» или «В процессе» и загрузите на странице все нужные курсы.
3. Скопируйте весь отображаемый список и вставьте в одно поле трекера. Укажите соответствующий раздел. Для общей копии обоих разделов выберите смешанный список и сохраните в тексте названия разделов.
4. Нажмите **«Учесть весь список»**. Точные нормализованные названия и проверенные старые названия применятся массово за одно действие. Ручной выбор нужен только для неоднозначных совпадений; неизвестные названия показаны отдельно и не создают новые курсы.

Копирование страницы передаёт только то, что вы загрузили и скопировали. Вставка не открывает аккаунт и не получает невидимые результаты. Если список неполный, прежние завершения, сертификаты и более высокий сохранённый прогресс не сбрасываются. Повторная вставка не создаёт копий курсов. Ручные исправления защищены; конфликтующие данные учитываются отдельно.

На карточке активного курса показывается фактический процент из списка, например **«В процессе · 67%»**. Если явно указано число выполненных заданий и их общее количество, процент рассчитывается и помечается **«по заданиям»**. Без этих данных отображается **«В процессе · процент пока неизвестен»**. Само открытие курса, время на сайте и оценка не создают процент прохождения. Явный статус завершения сильнее процента, который может относиться к оценке или дополнительным материалам; одни лишь 100% не подтверждают завершение.

Завершённый курс сразу исчезает из очереди продолжения и обновляется во всех связанных предметах. В общем плане он считается один раз. На обзоре видны результат проверки, **«Пройдено X из Y курсов моего плана · Z%»**, дата и источник последней проверки. При вставке источник подписан **«Вставленный список Coursera»** — это не официальная синхронизация с аккаунтом. Если в том же блоке найдена допустимая персональная ссылка сертификата, она появляется на завершённой карточке; отсутствие ссылки не мешает отметить курс пройденным.

### Необязательное расширение Chrome

Для настольного Chrome на экране проверки можно раскрыть **«Автоматический перенос через расширение Chrome»** и скачать `course-progress-extension.zip`. Установка выполняется пользователем вручную:

1. Распакуйте ZIP в постоянную папку.
2. Откройте `chrome://extensions`, включите «Режим разработчика» и выберите «Загрузить распакованное расширение».
3. Выберите папку, содержащую `manifest.json`.
4. Откройте значок расширения, поставьте отметку согласия и нажмите «Включить чтение моего прогресса».
5. Перезагрузите открытые страницы трекера и Coursera. Откройте «Моё обучение», затем «Завершённые» и «В процессе»; загрузите нужные строки списка.

Расширение читает только уже отображённые строки в «Моём обучении» после вашего включения. Оно не прокручивает страницу, не открывает разделы и не входит в аккаунт самостоятельно. Для старых завершений нужно открыть соответствующий раздел и загрузить список. После этого «Проверить мой прогресс» использует доступные результаты расширения; при активном подключении новые полученные результаты обновляются автоматически. Источник обозначен **«Расширение браузера · видимая страница Coursera»**.

Расширение не является официальным API Coursera: это локальное чтение отображённого DOM и передача распознанных результатов трекеру внутри браузера. Единственное API-разрешение расширения — `storage`; пароли, cookies, токены, сетевые запросы и внутренние API не читаются. Полный текст страницы не сохраняется и не отправляется на сервер. Перед сменой аккаунта Coursera выберите **«Отключить и очистить данные»**: расширение не устанавливает личность владельца через аккаунт. Уже сохранённые отметки трекера при отключении остаются. На телефоне и без установки расширения используйте массовую вставку.

Прямое официальное подключение к личным результатам в этой поставке не настроено. Обычный вход пользователя в Coursera сам по себе не даёт сайту на GitHub Pages авторизованного доступа. Официальные возможности разработческого доступа описаны в [Coursera Developer Platform](https://dev.coursera.com/get-started); отдельный университетский адаптер потребовал бы предоставленного и разрешённого доступа. Интерфейс не объявляет официальную синхронизацию при вставке списка или работе расширения.

### PDF, папка и отчёты

**PDF:** в разделе «Сертификаты» укажите имя владельца так, как оно записано в документе, затем загрузите файлы или подключите отдельную папку. Для автоматического сопоставления нужны читаемый текст, признаки выданного сертификата, однозначное название / проверенный псевдоним, подходящий вид документа и провайдер. Скан без текста, несовпадающее имя и неоднозначные записи требуют ручной проверки. OCR не включён. Сертификат программы не завершает её отдельные курсы.

PDF.js и совместимый worker входят в сборку. Ссылки извлекаются из текста и аннотаций PDF. Если ссылки нет, можно открыть сохранённый PDF или позднее добавить персональный URL. Переход на страницу курса сам по себе не завершает курс. Сайт проверяет форму и официальный домен ссылки, но не удостоверяет подлинность сертификата у платформы.

**Папка:** `showDirectoryPicker` доступен главным образом в настольных Chromium-браузерах на HTTPS. Приложение читает PDF непосредственно из выбранной папки, без обхода вложенных каталогов. Проверки выполняются при открытии, возвращении во вкладку и раз в минуту, пока она видима. Восстановление разрешения вызывается только кнопкой пользователя. Папку можно отключить. При отсутствии API используйте загрузку нескольких PDF. Размер одного импортируемого файла ограничен 40 МБ.

**CSV / JSON:** нужны `courseId` (стабильный ID каталога) или `title` (точное название / псевдоним), а также явное поле `status`. Дополнительно поддерживаются `provider`, `kind`, `completedAt`, `grade`, `certificateUrl`. CSV допускает запятую или точку с запятой; экран сопоставления колонок позволяет выбрать нестандартные заголовки. JSON отчёта — массив записей либо объект с массивом `rows`.

```json
[
  {"courseId": "Q12", "status": "new"}
]
```

Статусы: `new`, `active`, `done` (также распознаются распространённые русские и английские значения). Дата — `YYYY-MM-DD` или ISO 8601; неизвестную дату оставляйте пустой. Дата импорта не подставляется вместо даты окончания. Отсутствующая ссылка не означает отсутствие завершения. Для неизвестного названия выберите существующий курс вручную: импорт не создаёт новые позиции каталога.

Перед применением отчёта проверьте выбранные записи и конфликты. Пустые поля не стирают сохранённый сертификат или завершение. Историю документов и отмену привязки можно открыть в разделе «Сертификаты». Для переноса между устройствами используйте **Настройки и резервная копия → Экспорт JSON** и импорт полученного файла на другом устройстве.

## Хранение и ограничения

Прогресс, настройки, персональные URL и импортированные PDF хранятся в IndexedDB текущего браузера с отдельным пространством имён для пути приложения. Файлы не отправляются на сервер. Очистка данных браузера, другой профиль, другой домен или изменение пути сайта могут сделать прежнее хранилище недоступным — периодически экспортируйте резервную копию.

Резервная копия содержит личные данные: сохраняйте её у себя. Она переносит записи прогресса, но **не переносит PDF и разрешение на папку**. На другом устройстве загрузите документы заново. Не коммитьте резервные копии, отчёты, сертификаты или токены в публичный репозиторий.

Сайт не подключён к официальному API Coursera и не получает уведомления о выполнении последнего задания. Источники статусов — ручные отметки, локальные файлы, вставленный список или включённое пользователем расширение с видимыми результатами страницы. Сам сайт не читает другую вкладку; необязательное расширение читает отображённый DOM только после включения. Пароли, cookies и неофициальные API не используются. Автоматическая межустройственная синхронизация и приватный университетский адаптер не включены. Для первого открытия сайта требуется сеть; полноценный офлайн-режим с service worker не реализован.

## Структура и проверки

- `src/catalog.json` — обезличенный справочник со стабильными ID.
- `src/relations.json` — исходные связи SE, XLS и LIST без расширения каталога.
- `src/core.js`, `src/storage.js`, `src/pdf.js` — расчёты, локальное хранение и обработка PDF.
- `src/progress-import.js` — локальное распознавание массовой вставки; `src/extension-client.js` — проверяемый мост к необязательному расширению.
- `src/app.js`, `src/style.css` — интерфейс и hash-навигация.
- `tests/core.test.mjs` — проверки каталога, уникального прогресса, дедлайна, URL и правил импорта.
- `tests/progress-import.test.mjs` — распознавание точных названий, разделов, процентов, заданий и ссылок.
- `extension/` — исходники расширения; `node scripts/build-extension.mjs` создаёт ZIP в `public/` для загрузки с сайта.
- `.github/workflows/pages.yml` — проверка, сборка и публикация GitHub Pages.

`npm test` запускает логические проверки, `npm run build` проверяет production-сборку. `npm run test:browser` запускает Playwright в отдельном headless Chrome (нужен установленный Google Chrome).

Перед первой публикацией выполнены 15 логических и 8 браузерных проверок под `/aitu-course-tracker/`: каталог 109/28, поиск и сброс фильтров, сохранение статуса после перезагрузки, кнопка сертификата только после завершения, импорт PDF с текстом и ссылкой, отсутствие дублей, неизвестная дата завершения, резервная копия, последовательное сопоставление двух CSV, неизвестный PDF на проверку и отсутствие горизонтальной прокрутки на ширине 360 px. Просмотрены скриншоты обзорной страницы на компьютере и в мобильном размере. Проверены обе стороны границы дедлайна UTC+5.

Для текущего обновления прошли **42 логических и 19 браузерных проверок**. Дополнительно проверены обе темы и системное оформление, карточки и список, уменьшение анимаций, массовая вставка двух завершённых курсов и одного активного с 67%, сохранение после перезагрузки, повторная и неполная вставка, неизвестный процент, автоматический локальный мост и собранный content script расширения на DOM-образцах. Просмотрены скриншоты результата и мобильной карточки с 67%.

Расширение проверяется на DOM-образцах и через локальный мост; проверка с авторизованным реальным аккаунтом Coursera не заявляется. Эти проверки также не заменяют проверку ваших реальных PDF и браузерного разрешения на папку. При изменении структуры Coursera расширению может потребоваться обновление; массовая вставка остаётся доступной. Если публикация не удалась, откройте журнал упавшего задания в Actions; при 404 проверьте источник Pages, успешный deployment и префикс репозитория.
